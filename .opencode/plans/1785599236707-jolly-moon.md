## 0. Rulings, and the one that reversed

### 0.1 D2 — REVERSED. `sub_category` is already native; do not add a field, widen the enum.

The draft concluded "defer the field, build a sidecar," on recon's reading that HG stores four fields with `category ∈ {outcome, process}`. The operator ruling supersedes it from the primary spec: **`category` is a stored 4-value enum — `"Outcome 1.1"`, `"Outcome 1.2"`, `"Outcome 2.1"`, `"Process"`.**

That changes the answer completely. AGENTS.md rule 24's `sub_category` — *"the single highest-leverage schema change available"* — is **already present in HarmonyGames**, carried in the `category` field's value space rather than as a new key.

- **No new field.** Adding one would still trip the binary *"adds an unsupported rubric field"*.
- **No sidecar for HG.** Overlap, redundancy and verb-convention checks become computable directly from `category`.
- **No change for the other four.** They keep `{outcome, process}`. Rule 24 stays open for them; out of scope (never edit existing-universe behavior).
- Implementation is a per-framework `rubric_category_enum` flag, not a branch.

**One unresolved tension, recorded as HG-U7 rather than guessed.** Recon measured the shipped, QC-**passed** `QC_Tasks/QC_Passed/Task1_6a625f3ea428e7b7d971e57f_HG/7_Rubrics.json` as 80 objects with `Counter({'outcome': 80})` — lowercase, un-suffixed. If the spec enum is the 4-value set, that file uses an invalid category on all 80 criteria and should have tripped a binary sub-dimension, yet it sits in `QC_Passed`. Spec and shipped artifact disagree. **T5.7 measures before it validates** (census across all 10 HG tasks), accepts the spec enum, and flags the legacy form as a pinned deviation. Not resolved by assumption in either direction.
