# Extend eval pipeline to V4/StarPM (zero Brookfield regression) — Execution Task Graph

> **For agentic workers:** Execute strictly wave-by-wave. Each wave's GATE task must be GREEN before the next wave starts. Parallelize only WITHIN a wave, and never put two tasks that edit the SAME file in the same parallel group. Every Python task is TDD: write the named failing test FIRST, watch it fail for the right reason, then implement.

**Goal:** Add a second universe (StarPM) + V4 framework to the existing single-universe (Brookfield/V3) eval-authoring pipeline with byte-identical Brookfield behavior, deterministic typed QC, per-task version-scoped routing, and a rebuilt SSOT-grounded feedback contract.

**Architecture:** ALREADY DECIDED + Oracle-reviewed (see `.omo/ulw-v4starpm-notepad.md` → ARCHITECTURE OF RECORD, items 1-12). This document does NOT re-derive architecture; it decomposes it into atomic, wave-ordered, independently-verifiable tasks. Do not re-open any architecture decision.

**Tech Stack:** Python 3 stdlib-only (validators, no third-party runtime deps), pytest for the test/golden harness (stdlib `unittest` acceptable fallback if pytest absent), Markdown/JSON deliverables + runbooks.

## Global Constraints (apply to EVERY task)

- **Zero Brookfield regression / 100% parity.** Proof = golden-master byte-identical (`python Validators/tests/build_goldens.py --check` exits 0), except where a signed-off W3 divergence is explicitly recorded.
- **Never edit Brookfield universe data.** `Brookfield_Base_Universe/**` and the 23 `Submitted-Tasks/*` + `QC_Tasks/**` fixture deliverables are READ-ONLY. Hardness/behavior comes from descriptors + routing, not universe edits.
- **500-word prompt cap + no em-dash/en-dash are UNIVERSAL invariants** (stay in root AGENTS.md). Profile-specific rules (no-universe-edits, 40-call floor, retention codes, `brookfieldcpas.com`, account numbers, param-trap words) are DEMOTED to routed descriptor/card and must NOT appear literally in root AGENTS.md, runbooks, or format cards after W6.
- **Deterministic binary QC only.** Structural parse + typed SSOT cross-ref (Decimal-cents for money; case-normalized set membership for email/id/date). No grep/substring-on-blob grounding.
- **Fail-loud, never silent-skip.** Missing split / missing tool-defs = hard FAIL (not PASS-by-omission).
- **Routing SSOT = explicit declare.** `_aux/universe.txt` (from `--universe`) is authoritative. Auto-detect is a FAIL-LOUD guard only (hard-error on contradiction/ambiguity; Brookfield+StarPM share `slack.*`/`linear.*` → never silent-infer). Not stored in `4_Changelog.json`.
- **Descriptor split on 2 axes:** UNIVERSE FACTS (thin, derived from `7_/8_Server_Tools_Details.json` + per-task data) vs FRAMEWORK PROFILE (density_floor, injection_enabled, models, phase/gate config, TOO_EASY). Task binding = (universe, framework); today only `(brookfield,v3)` and `(starpm,v4)`.
- **No `quick` category on any validator-algorithm or runbook task.**
